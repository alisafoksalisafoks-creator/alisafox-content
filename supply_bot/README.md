# Бот поставок FBO AlisaFox

Отдельный Telegram-бот со строгим расчётом поставок на склады Ozon. Общие советы остаются в аналитическом боте,
здесь только расчёт: направление (кластер) → артикулы → количество полными моно-коробами.

Бот **только читает** Ozon, «Мой склад» и Google-таблицы. В кабинете ничего не создаёт и в таблицах ничего не меняет.

## Что умеет

Старт: **FBO** / **FBS**. FBS — заглушка, правила пропишем отдельно.

**Доступ** (кнопка видна только владельцу): новый человек пишет боту /start, владельцу приходит запрос
с кнопками «Пустить» / «Отказать». Можно добавить по chat id или убрать человека. Список хранится
в `SUPPLY_BOT_DATA/users.json`. Те, кто вписан в `SUPPLY_BOT_CHATS`, остаются всегда; управляет доступом
`SUPPLY_BOT_ADMINS` или, если пусто, первый id из `SUPPLY_BOT_CHATS`.

Меню FBO:

| Кнопка | Что делает |
|---|---|
| Распределение по магазину | Сводка на экране. Под ней: «Показать по складам», «Всё верно, прислать файлом», «Исправить кол-во», «Пересчитать» |
| Сформировать отчёт Excel | Сразу присылает файл со всеми листами по текущему расчёту (с учётом ручных правок) |
| По артикулу | Вводите артикул → потребность по каждому складу, остаток на нашем складе, пустые кластеры |
| По направлению | Выбираете кластер → список артикулов и количество |
| Заказать | Что на Ozon скоро закончится или уже 0, а на нашем складе нет или не хватает. Только прибыльные артикулы: прибыль на 1 шт бот считает сам (отчёт о реализации Ozon с 1-го числа прошлого месяца, услуги Ozon, себестоимость «Мой склад», УСН 7%), минусовые не включаем |
| Пустые кластеры | Кластеры без единого нашего товара → «рекомендуется отгрузка в кластер». Хиты, которых нет во всём кластере |
| Решить / стоп | Новинки, выкуп < 85%, рейтинг < 4,6, платное хранение ≤ 28 дней, нет статуса |
| Скоро платно | Что уже платное или станет платным в ближайшие 28 дней — не отгружаем |
| Сверка с «Моим складом» | Минусы в «Моём складе» и заявки больше остатка |
| Обновить данные | Заново скачать Ozon, «Мой склад», таблицы |

Файл Excel уходит по кнопке «Всё верно» под сводкой или «Сформировать отчёт Excel» в меню FBO. Листы: «Лист распределения» (склад / артикул / кол-во / короб),
«Потребность по направлениям», «Пустые кластеры», «Не попало в план», «Решить - стоп», «Заказать», «Скоро платно»,
«FBO+FBS», «Баланс нашего склада», «Параметры».

**Исправить кол-во:** склад → артикул → число. Бот подгоняет до ближайших полных коробов и свободного остатка,
помечает «вручную» и предупреждает, если запас выходит больше 30 дней. Правки живут до сброса.

## Как считает

1. Направление — кластер целиком: спрос = отгрузки FBO со всех складов кластера за 14 полных дней без отмен ÷ 14 × коэффициент сезона.
   Склад приёмки — подсказка: наш основной склад кластера по отгрузкам за 30 дней, окончательно выбирается в кабинете.
2. Потребность кластера = спрос × 30 дней от сегодня, доставка внутри (если доставка дольше 16 дней — L + 14) − (доступно + в пути на всех складах кластера).
3. Статус из таблицы AlisaFox, лист «Юнит экономика Алиса», «Статус ЗАЯВОК»: «Грузим» и «Частично грузим» — считаем;
   «Не грузим» — не везём; «Новинки» — в «Решить» за стратегией первой поставки.
4. Наш склад: «Мой склад», «1. Основной склад», остаток − резерв − заявки Ozon, которые ещё не уехали.
   Ноль — «у вас нет товара, везти нечего». Не хватает — приоритетным кластерам артикула (по продажам, вместе 50% его продаж) запас
   на 14 дней, остальным на 7, остаток — по убыванию продаж; нехватка — в «Заказать».
5. Москва и Питер — обычные кластеры, отдельных складов нет.
6. Короба: 1 короб = 1 артикул = 1 направление. Кванты — таблица «РАЗМЕЩЕНИЕ ПО КОРОБАМ».
   Сначала большие короба, остаток — коробом поменьше; вверх только если запас не уйдёт дальше 30 + 3 дней.
7. Приоритет: «срочно» — запаса меньше срока L, «наверх» — хит (от 1 шт/день) с запасом меньше 14 дней.
8. Дата отгрузки — ближайший пн, ср или пт.
9. Склады за пределами РФ (Казахстан, Беларусь, Армения, Узбекистан и др.) не считаем и в сигналы не берём.

Все пороги — в `config.py`.

Сезонность: положите `season.tsv` в `SUPPLY_BOT_DATA` (категория комиссии и 12 коэффициентов через табуляцию).
Нет файла — коэффициент 1.

## Запуск на сервере

Нужно: Ubuntu 24.04, 2 vCPU, 2 ГБ RAM, 20 ГБ SSD, Python 3.12.

```bash
sudo useradd -r -m -d /opt/supply-bot supplybot
sudo -u supplybot git clone <репозиторий> /opt/supply-bot/src
cd /opt/supply-bot && sudo -u supplybot python3 -m venv venv
sudo -u supplybot venv/bin/pip install -r src/supply_bot/requirements.txt
sudo mkdir -p /var/lib/supply-bot && sudo chown supplybot /var/lib/supply-bot
sudo cp src/supply_bot/env.example /etc/supply-bot.env && sudo chmod 600 /etc/supply-bot.env   # заполнить
sudo cp src/supply_bot/deploy/supply-bot.service /etc/systemd/system/
sudo systemctl enable --now supply-bot
```

Доступы:

* новый бот у @BotFather → `TELEGRAM_SUPPLY_BOT_TOKEN`;
* chat id владельца и команды → `SUPPLY_BOT_CHATS` (бот подскажет id на /start);
* ключ Ozon Seller «только чтение», токен «Моего склада» «только чтение»;
* сервисный аккаунт Google: ключ JSON на сервер, его почте — доступ «Читатель» к таблице AlisaFox и таблице квантов.
