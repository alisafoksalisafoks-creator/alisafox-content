# Подключение МойСклад и TrueStats к облачной среде

Подготовлено: 20.10.2026, обновлено 25.10.2026. Складская программа — МойСклад (JSON API 1.2). Статус: МойСклад работает, TrueStats — ключ принят, методы уточняем.

## 1. МойСклад

**Что внести в Allowed domains (одна строка):**

```
api.moysklad.ru
```

- Это единственный домен API (старый online.moysklad.ru для API больше не используется). Сайт с документацией dev.moysklad.ru вносить не нужно.
- Проверка из среды: 20.10.2026 до внесения — закрыт; после внесения 20.10 и 25.10.2026 — работает (200).

**Авторизация (по документации JSON API 1.2):**
- Заголовок `Authorization: Bearer <токен>` и `Accept-Encoding: gzip` (он есть во всех официальных примерах, будем всегда отправлять).
- Базовый адрес: `https://api.moysklad.ru/api/remap/1.2/`.
- Токен получает права того сотрудника, под которым его создали. Отдельной галочки «только чтение» у токена нет.

**Как сделать токен только на чтение:**
1. МойСклад → Настройки (шестерёнка) → Сотрудники → создать сотрудника, например «API чтение». Учтите: по тарифу это может занять платное место пользователя.
2. Дать ему роль, где у нужных разделов (товары, остатки, документы, отчёты) включён только «Просмотр», без создания, редактирования и удаления.
3. Войти под этим сотрудником → Настройки → Обмен данными → Токены → «Создать токен». Скопировать токен (покажут один раз).
4. Если отдельного сотрудника заводить не хотите, можно сделать токен под своим аккаунтом. Тогда у него будут все ваши права, а чтением ограничусь я сам. Это рабочий, но менее безопасный вариант.

Важно: если позже создать токен через API-метод `/security/token`, старые токены этого сотрудника отзываются. Через интерфейс «Токены» такого нет.

**Переменная среды:** `MOYSKLAD_TOKEN`.

**Как я проверю:** `GET https://api.moysklad.ru/api/remap/1.2/entity/organization` → 200 (только чтение). Потом остатки: `GET .../report/stock/all`.

## 2. TrueStats

Обновлено 25.10.2026. У пользователя есть API-ключ из кабинета TrueStats (вид `ts_…`).

**Allowed domains** (каждый отдельной строкой):

```
truestats.ru
api.truestats.ru
```

**Переменная среды** — одна строка: `TRUESTATS_TOKEN=ts_ваш_ключ` (без кавычек, без слов curl, -H, X-Api-Token).

- Заголовок запроса: `X-Api-Token: <ключ>`. Его подставляю я.
- Статус 23 и 25.10.2026: ключ в среде, сервер его принимает (на неверный ключ отвечает 401 «Невалидный или истёкший API-токен», на наш — 403 «Эндпоинт недоступен по API-токену»).
- Какие методы открыты для ключа, пока неизвестно: публичная схема (api.truestats.ru/api/docs) показывает только служебные методы. Нужен список методов из кабинета TrueStats или от их поддержки.
- Кабинет app.truestats.ru в среде закрыт; добавлять, только если будем искать методы в коде кабинета.
- Пока методов нет — работаем выгрузками в Excel: себестоимость по артикулам, прибыль по SKU за месяц.

## 3. Как внести в среду

1. Откройте настройки проекта → Environment → меню «Cloud environment» → шестерёнка у выбранной среды.
2. **Network access** → уровень Limited → поле **Allowed domains**: добавьте строку `api.moysklad.ru`. Остальные строки не трогайте, галочку «Allow package managers» оставьте включённой.
3. В той же среде токен: раздел **Network secrets** (в старой версии приложения — API credentials), если он есть; иначе **Environment variables** строкой `MOYSKLAD_TOKEN=значение`.
4. Сохраните. Новые настройки подхватывает новая сессия — напишите в этот тред, я проверю доступ.

Ключ в чат не присылайте. Если прислали случайно — удалите сообщение и перевыпустите токен.

Документация: https://dev.moysklad.ru/doc/api/remap/1.2/ ; шаги по среде: https://code.claude.com/docs/en/cloud-environments#network-access
